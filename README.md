# NodeTelehealth Marketing Automation

A macOS desktop control center (Electron) for a serverless Google Apps Script backend that plans, writes, renders and publishes Florida-only organic marketing for **nodetelehealth.com**: blog posts (WordPress / Webflow), short vertical videos (ElevenLabs + HeyGen or Creatomate) and social posts.

```
MTWOB/
├── gas-backend/                 Google Apps Script project (paste into script.google.com)
│   ├── appsscript.json          Manifest: scopes, web-app settings, America/New_York timezone
│   ├── Code.gs                  Router (doGet/doPost), handshake auth, initializer, Sheets "database"
│   ├── GuardManager.gs          Kill switch, tool toggles, trigger teardown/restore, guarded HTTP wrapper
│   ├── ClaudeAgent.gs           Anthropic API client, compliance guardrails, blog/social/video generators
│   ├── ContentQueue.gs          Planning, queue state machine, generate + publish cycles
│   ├── CMSPublisher.gs          WordPress REST v2, Webflow CMS Data API v2, webhook adapter
│   ├── VideoPipeline.gs         ElevenLabs TTS, HeyGen, Creatomate / JSON2Video, async render poller
│   ├── SocialPublishers.gs      Facebook, Instagram Reels, X, LinkedIn, YouTube Shorts, TikTok, Google Business
│   ├── AnalyticsSync.gs         Metrics + cost harvester, dashboard aggregator
│   └── dev/                     Local test harness (not deployed)
│       ├── harness.js           Runs the .gs files in Node with simulated Google services and APIs
│       ├── smoke-test.js        25 backend checks
│       └── serve.js             Local backend at http://127.0.0.1:8787/exec for trying the app
└── mac-desktop-app/
    ├── package.json             electron + electron-builder (dmg, arm64 + x64)
    ├── main.js                  Backend client, tray + kill switch, notifications, export, media cache
    ├── preload.js               IPC bridge (contextIsolation, sandbox)
    ├── index.html / styles.css / renderer.js    Dashboard UI
    ├── assets/ build/           Tray icons and app icon (generated by scripts/make-icons.js)
    └── scripts/                 make-icons.js, e2e.js (Electron end-to-end test)
```

## What has and has not been tested

- **Tested:** all backend logic (kill switch, toggles, queue workflow, publishers' control flow, aggregator) runs in the local harness — `node gas-backend/dev/smoke-test.js`. The Electron app was driven end to end against that harness in light and dark mode — `scripts/e2e.js`.
- **Not tested:** nothing has been run on Google's servers or against the real Claude, WordPress, Webflow, ElevenLabs, HeyGen, Creatomate, JSON2Video, Pexels, Meta, X, LinkedIn, YouTube, TikTok, Google Business or GA4 APIs. Request shapes were written from API knowledge, not verified live. Use each **Save & Test** button in the setup wizard, keep **Approval mode** on, and publish one item per channel by hand before switching to Autonomous.
- The `.dmg` itself has not been built (that requires macOS); packaging was validated with an unpacked Linux build.
- The compliance filter is a prompt plus a keyword scan. It is not legal review. Have counsel check the guardrail text in `ClaudeAgent.gs` against HIPAA marketing rules and Fla. Stat. § 456.47.

## 1 · Deploy the Apps Script backend

1. Go to <https://script.google.com> → **New project**. Name it `NodeTelehealth Marketing`.
2. **Project Settings** → tick **Show "appsscript.json" manifest file in editor**.
3. Replace `appsscript.json` with the one in `gas-backend/`, and create one script file per `.gs` file (same names), pasting the contents. Do not upload `dev/`.
   With [clasp](https://github.com/google/clasp) instead: `npm i -g @google/clasp && clasp login && cd gas-backend && clasp create --type standalone --title "NodeTelehealth Marketing" && clasp push` (add `dev/**` to `.claspignore`).
4. In the editor select the function **`initializeSystem`** and click **Run**. Approve the permission prompt (Advanced → Go to project). This creates:
   - the spreadsheet `NodeTelehealth_Marketing_DB` with tabs `Config`, `Tool_States`, `Content_Queue`, `Video_Render_Jobs`, `Published_Logs`, `Analytics_Metrics`, `Florida_Keywords`, `API_Cost_Log`;
   - the Drive folder `NodeTelehealth_Media_Assets` with `Voiceovers`, `Videos`, `Blog_Covers`, `Broll`, `Payloads`;
   - four time-driven triggers, every tool toggle set to **OFF**, and the **handshake token**.
5. Open **Execution log** and copy `handshake_token`.
6. **Deploy → New deployment → Web app** → *Execute as:* **Me**, *Who has access:* **Anyone** → **Deploy**. Copy the URL ending in `/exec`.
   After editing code later: **Deploy → Manage deployments → Edit → Version: New version** (the URL stays the same).

"Anyone" is required because the Mac app is not signed in to Google; every request must carry the handshake token. To rotate it, run `rotateHandshakeToken` in the editor and update the app.

### Drive permissions

Rendered MP3/MP4 files are shared as **Anyone with the link → Viewer** so Creatomate, Instagram and the in-app player can fetch them. They are marketing assets intended for publication. If your Google Workspace blocks external link sharing, allow it for this folder or the video pipeline cannot hand files to those services.

- Put cover images in `Blog_Covers` — one is picked at random as the WordPress featured image.
- Put your own vertical clips in `Broll` — used when no Pexels key is set.

### Optional Google services

- **GA4 and YouTube** use the script owner's Google account. The manifest enables the Analytics Data and YouTube advanced services; the owner needs Viewer access to the GA4 property.
- **Google Business Profile** needs API access approved by Google for the script's Cloud project.
- Remove scopes you don't use from `appsscript.json` to shorten the consent screen.

## 2 · Build and install the Mac app

Requires macOS and Node.js 20+.

```bash
cd mac-desktop-app
npm install
npm start                 # run in development
npm run build:mac         # dist/NodeTelehealth-Marketing-1.0.0-arm64.dmg and -x64.dmg
npm run build:mac:universal   # one universal .dmg instead
```

Open the `.dmg` and drag the app to Applications. The build is unsigned, so on first launch right-click the app → **Open** (or run `xattr -cr "/Applications/NodeTelehealth Marketing.app"`). To sign and notarize, set `CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID` before building.

Try it without deploying anything:

```bash
npm run dev:backend       # simulated backend + sample data; prints a URL and token
npm start                 # paste them into Settings & Setup
```

## 3 · Connect and configure

In the app, **Settings & Setup** walks through seven steps: backend URL + token, Claude, CMS, ElevenLabs, video, social tokens, GA4. API keys are sent once to the backend and stored in `ScriptProperties`; the app only ever gets back "saved ••••1234". The Mac stores just the URL and the handshake token (encrypted with the Keychain).

Then switch on the tools you want in **Tool Controls**.

### WordPress application password

1. WordPress admin → **Users → Profile** (a user with the Editor or Administrator role).
2. **Application Passwords** → name `NodeTelehealth Marketing` → **Add New Application Password**.
3. Paste the site URL (`https://…`), username and generated password into step 3 of the wizard → **Save & Test**.

Yoast / Rank Math fields are sent with each post, but WordPress only stores meta keys registered for REST. Add this as `wp-content/mu-plugins/nt-seo-meta.php`:

```php
<?php
add_action('init', function () {
  foreach (['_yoast_wpseo_title','_yoast_wpseo_metadesc','_yoast_wpseo_focuskw','rank_math_title','rank_math_description','rank_math_focus_keyword'] as $key) {
    register_post_meta('post', $key, ['show_in_rest' => true, 'single' => true, 'type' => 'string',
      'auth_callback' => function () { return current_user_can('edit_posts'); }]);
  }
});
```

### Webflow API token

1. Webflow → **Site settings → Apps & integrations → API access → Generate API token** with **CMS: Read and write** (and **Sites: Read and write** for publishing).
2. Collection ID: **CMS → Blog Posts → Settings**.
3. The collection needs fields with slugs `post-body` (rich text), `post-summary` and `seo-description`. Other slugs can be mapped in the `Config` → `webflow_field_map` setting.
4. Webflow strips `<script>` from rich text, so add the FAQ JSON-LD in the collection page template if you want it.

### Other credentials

| Service | What to enter |
|---|---|
| Claude | API key from console.anthropic.com. Models: `claude-sonnet-4-6` or `claude-opus-4-6`. |
| ElevenLabs | API key + voice ID. Models: `eleven_flash_v2_5` / `eleven_turbo_v2_5`. |
| HeyGen | API key + avatar ID. |
| Creatomate | API key. Template ID is optional; without it a built-in 9:16 layout is used. Template element names: `Voiceover`, `Hook`, `CTA`, `Background-1…N`. |
| Pexels | Free API key for portrait stock b-roll. |
| Facebook / Instagram | Page ID, long-lived Page access token (`pages_manage_posts`, `instagram_content_publish`, `read_insights`), Instagram business account ID. |
| X | OAuth 1.0a keys for an app with Read and Write. Text and threads only. |
| LinkedIn | Access token with `w_organization_social` + organization ID. |
| YouTube | Nothing (uploads to the script owner's channel), or an OAuth client + refresh token for another channel. |
| TikTok | Content Posting API access token. Unaudited apps can only post privately; after audit set the script property `TIKTOK_PRIVACY_LEVEL=PUBLIC_TO_EVERYONE`. |
| Fallback | A Buffer / Make.com webhook URL is used for any network without native credentials. |

## How the controls work

**Kill switch (`MASTER_KILL_SWITCH`).** Engaging it from the header, the menu bar or ⌘⇧K deletes every trigger, so Google runs no background jobs. Every generator, publisher and cron runner starts with `assertSystemActive()`, and every outbound request goes through one wrapper that re-checks the switch — a job already running stops at its next API call. Resuming recreates exactly one trigger per job.

Two Apps Script limits shape this:

- Web apps cannot read request headers or set status codes. The token travels in the JSON body, and "423 Locked" is returned as `{ "ok": false, "status": 423, "code": "SYSTEM_HALTED" }` inside an HTTP 200.
- State reads, toggles and settings stay reachable while halted — otherwise the switch could not be turned off. They never call an external API.

**Tool toggles.** Each of the 12 switches is checked when planning (a disabled channel is never written for) and again immediately before each API call.

**Workflow modes.**

| | Autonomous | Human-in-the-Loop Approval (default) |
|---|---|---|
| Blog | Published live | Sent to the CMS as a draft; **Publish Now** takes it live |
| Social | Scheduled and posted | Waits for **Approve** |
| Video | Rendered and posted | Script waits for approval before any voice/render spend; finished MP4 waits for **Publish Now** |

Content flagged by the compliance filter is held in both modes.

**Dashboard numbers.** Florida city trends come from GA4. Channel metrics come from each platform's API. Dollar figures are estimates: logged usage × the unit prices in **Agent Control → Cost & value assumptions**. Set those to match your plans.

## Quotas to know

- Apps Script requests to external APIs time out after about 60 seconds; blog generation is sized to fit. Each run is capped at 6 minutes.
- Consumer Google accounts get 90 minutes of trigger runtime per day. The 5-minute render poller exits immediately when nothing is rendering.
- Files over 50 MB cannot be moved through Apps Script; 30–45 second vertical videos are far below that.
